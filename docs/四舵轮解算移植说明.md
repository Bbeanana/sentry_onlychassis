# 齐奇战队四舵轮解算移植说明

已将山东理工大学齐奇战队开源底盘中的舵轮解算与转向优化接入本工程的 `RobotChassisKinematics`。控制对象为四个 M3508 驱动电机和四个 GM6020 舵向电机。本次完成代码接入和 STM32H723 固件编译，尚未上板或实车验证。

## 1. 文件与控制链路

| 文件 | 内容 |
| --- | --- |
| [alg_swerve.h](../Skywalker/Algorithm/Inc/alg_swerve.h) | 四轮向量、最优角和轮速限幅接口 |
| [alg_swerve.c](../Skywalker/Algorithm/Src/alg_swerve.c) | 独立于 HAL、FreeRTOS 和电机驱动的解算实现 |
| [app_robot.c](../Skywalker/Application/Src/app_robot.c) | 遥控指令、轮组配置、解算接入、电机 PID 与 CAN 输出 |
| [qiqi-swerve-MIT.txt](licenses/qiqi-swerve-MIT.txt) | 保留源工程的 MIT 版权声明与许可 |

控制链路如下：

```text
UART7 或 DT7 / 键盘速度指令
    → 统一前/左坐标输入（vx 向前、vy 向左）
    → 遥控云台相对角转换；小陀螺 5 ms 航向前馈及降速
    → IMU 角速度补偿
    → SwerveResolve：计算四轮合速度、方向
    → 本车舵向零位和安装方向换算
    → SwerveOptimizeWheel：最短转角、驱动反向、cos³ 补偿
    → SwerveLimitWheelSpeeds：四轮等比例限速
    → M3508 目标角速度 + GM6020 目标角度
    → 本车目标角度斜坡、PID、反馈超时和转向放行逻辑
    → FDCAN2 驱动输出 + FDCAN1 舵向输出
```

CMake 已递归收集 `Skywalker/Algorithm/Src/*.c`，重新配置时会纳入新模块，无需添加 HAL 或第三方算法库。

## 2. 移植范围及原代码适配

源代码位于齐奇战队工程的 `firmware/User/Application/src/chassis_task.c`，主要参考：

- `chassic_rudder_preliminary_A_S_solution`：平移与旋转速度分量相加，用 `sqrtf` 求轮速、`atan2f` 求舵角。
- `Rudder_motor_relative_angle_control`：误差包裹到 ±180°，超过约 90° 时采用等价舵角并反转驱动轮，轮速乘 `cos(error)³`。
- `chassis_speed_control_set`：超过轮速上限时统一缩放四轮目标。
- `chassis_set_contorl`（源文件中的拼写）内的 `CHASSIS_VECTOR_SPIN` 分支：小陀螺平移的坐标变换、5 ms 航向补偿和 0.4 / 0.3 平移缩放。

适配时沿用目标工程的坐标、单位、尺寸配置和驱动安装方向。按本车四个 GM6020 均倒置安装的机械配置，舵向安装符号设为 -1。源工程的固定 `wz × 0.70710678` 分量未显式包含轮距，其速度换算也存在未说明的经验缩放；本工程采用轮组坐标生成旋转分量，输入仍为 m/s、rad/s。

源工程右前轮单独取负，并在 CAN 发送函数中固定清零左前、右后两路。本工程的驱动方向使用已有四轮配置，四路都经过解算、PID 和 CAN 打包。

源工程的 `Matlab_PID_Calc` 实现没有公开；本次继续使用目标工程已有的 M3508 速度 PID 和 GM6020 位置/速度串级 PID。源工程的状态机、上板通信、超级电容控制和存在单位问题的角速度正解不属于本次移植范围。

## 3. 坐标系与四轮解算

本车坐标：俯视 `+X` 向前、`+Y` 向左，角速度 `ω` 逆时针为正。数组顺序固定为左前、右前、左后、右后。实车轮组按俯视左上角为 ID1、逆时针递增：ID1 左前、ID2 左后、ID3 右后、ID4 右前。CAN 槽位通过 `kRobotChassisCanSlotWheelIndex={0,2,3,1}` 映射到物理轮位数组。

遥控输入采用 `vx=ch3/660`、`vy=-ch2/660` 的归一化方向，经死区、限幅后乘各轴速度上限；键盘 W/S 对应正/负 vx，A/D 对应正/负 vy。遥控前/左方向以云台朝向为参考，经 USART10 相对角转换后进入车身坐标。UART7 第一组线速度为 vx（车头），第二组为 vy（车左），不交换或取反。所有速度最终统一为车身前/左坐标，四轮安装方向和编码器零位由原电机配置处理。

令半宽为 `W`、半长为 `L`，轮组坐标与合速度为：

| 索引 / 轮组 | `(x_i,y_i)` | `u_x` | `u_y` |
| --- | --- | --- | --- |
| 0 / 左前 | `(+L,+W)` | `vx-ωW` | `vy+ωL` |
| 1 / 右前 | `(+L,-W)` | `vx+ωW` | `vy+ωL` |
| 2 / 左后 | `(-L,+W)` | `vx-ωW` | `vy-ωL` |
| 3 / 右后 | `(-L,-W)` | `vx+ωW` | `vy-ωL` |

```text
轮速 s = sqrt(u_x² + u_y²)
相对前向舵角 θ = atan2(u_y,u_x)
原始电机目标角 = wrap(前向零位 + 舵向安装符号 × θ)
```

四个 GM6020 均倒置安装，`kRobotSteeringDirection` 四项设为 -1，所有运动模式使用 `电机目标角=wrap(前向零位-θ)`。例如轮组相对前向需要逆时针偏转 45°，电机编码器目标为各自零位减 45°；顺时针偏转则相反。原代码中“仅拨轮原地旋转时把舵角取反”的分支不再单独使用，避免安装符号重复取反。纯旋转、平移及混合运动统一经过同一个映射，最优角和驱动反向在安装映射之后执行。

按倒置安装符号还原轮组的物理方向后，纯旋转四轮速度应与各轮到中心的连线垂直。解算实现已覆盖四个零位的正负 45° 映射、正负原地旋转、前后切换和混合运动。

## 4. 最优角、补偿与限速

读取 GM6020 实际角度，计算 `e=wrap(target-feedback)`：

```text
e >  π/2：e -= π，驱动方向 = -1
e <= -π/2：e += π，驱动方向 = -1
其余：驱动方向 = +1

最终电机目标 = wrap(feedback + e)
驱动轮线速度 = s × 驱动方向 × cos(e)³
```

最终舵向误差不超过约 90°；前后方向直接切换时可以保持舵角、改变驱动符号。沿用源代码的边界约定：+90° 不反向，-90° 反向；两种情况的补偿速度都约为零。

没有旋转分量时，补偿计算对小于 `0.05 rad` 的误差按 0 处理；该死区不会清除位置环误差。有旋转分量时关闭该补偿死区。

补偿后四轮线速度取绝对值最大值 `s_max`，若超过 `kRobotChassisMaxWheelSpeedMps=5.0`，四轮都乘 `5/s_max`。该上限与目标工程原有 5 m/s 直行设定保持一致，同时限制斜向合速度。

电机角速度换算为：

```text
M3508 given_omega = 安装符号 × 轮线速度 × 电机到轮子的减速比 / 轮半径
```

全部角度使用弧度，编码器角度转换沿用目标驱动的 `2π/8192`。零速度时应用层保持现有目标或进入静止卸力，避免对零向量调用 `atan2` 后强制打舵。

## 5. 电机与当前配置

| 轮组 | M3508 反馈 / 输出 | GM6020 反馈 / 输出 | 前向零位编码值 | M3508 安装符号 |
| --- | --- | --- | --- | --- |
| 左前（ID1） | FDCAN2 `0x201` / `0x200` 第 1 槽 | FDCAN1 `0x205` / `0x1FE` 第 1 槽 | 3060 | -1 |
| 右前（ID4） | FDCAN2 `0x204` / `0x200` 第 4 槽 | FDCAN1 `0x208` / `0x1FE` 第 4 槽 | 986 | -1 |
| 左后（ID2） | FDCAN2 `0x202` / `0x200` 第 2 槽 | FDCAN1 `0x206` / `0x1FE` 第 2 槽 | 2383 | -1 |
| 右后（ID3） | FDCAN2 `0x203` / `0x200` 第 3 槽 | FDCAN1 `0x207` / `0x1FE` 第 3 槽 | 4390 | -1 |

四轮舵向安装符号均为 -1，匹配本车 GM6020 倒置安装。四个 M3508 的驱动安装符号也统一为 -1（ID3、ID4 实测平移方向与整体相反）；CAN 原始编码器、转速、电流反馈及 PID 输出方向不取反。本次没有复制源工程的零位。

CAN 反馈按电机 ID 接收后再写入物理轮位数组；发送时将物理轮位数组按电机 ID 1、2、3、4 重排到 `0x200` 和 `0x1FE` 的四个槽位。底盘 M3508 与舵向 GM6020 使用同一组轮组 ID，共用 `{0,2,3,1}` 映射。因此右前物理轮位使用电机 ID 4，右后使用 ID 3，左后使用 ID 2，运动学和安装方向参数仍对应实际轮位。

目标工程当前几何/速度配置也予以保留：

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| `kRobotChassisHalfLengthM` | 0.106066 m | 前后半轮距 |
| `kRobotChassisHalfWidthM` | 0.106066 m | 左右半轮距 |
| `kRobotWheelRadiusM` | 0.01 m | 原工程用于速度换算的值，需核对真实轮径 |
| `kRobotDriveReductionRatio` | `3591 / 187 ≈ 19.2` | M3508 到轮子的减速比；轮径仍需按实车核对 |
| `kRobotChassisMaxWheelSpeedMps` | 5.0 m/s | 本次新增的四轮线速度上限 |
| `kRobotSteeringTargetRateMaxRadps` | 4.0 rad/s | 保留的舵角目标推进速率 |

**相同电机型号不能确定相同轮径、传动比和编码器零位。** 当前减速比已改为 M3508 的 `3591 / 187 ≈ 19.2`，但轮半径仍是原工程的 `0.01 m` 占位值；相应“m/s”设定是否等于实车速度取决于轮径和减速比的准确性，必须按实车核对。

## 6. 保留的控制保护

保留遥控器失联处理、四路电机反馈超时、静止卸力、舵角目标斜坡、PID 限幅及现有功率/电流限制。

普通运动使用全局误差滞回：最大最终舵角误差小于 `0.10 rad` 才放行，放行后超过 `0.40 rad` 则停驱动。检查对象为**最终优化后的舵角目标**，避免中间斜坡目标贴近反馈而提前放行。

小陀螺使用独立的 `spin_drive_tracking` 状态：每次进入小陀螺时，仍须四轮最大最终舵角误差小于 `0.10 rad` 才启动；运行中不再因为单轮误差超过 `0.40 rad` 而清零全车驱动及重置驱动 PID。改由各轮已有的 `cos³` 补偿连续降低轮速，误差接近 90° 时该轮驱动目标趋近零，其他对齐的轮组仍可输出。这一行为参考源工程的小陀螺控制，可消除普通运动硬切断逻辑带来的反复启停，但不会提高舵向电机的实际跟踪能力。

任意 M3508 或 GM6020 反馈失效仍会清零四轮驱动，并解除小陀螺放行状态；反馈恢复后必须重新满足初始对齐条件。静止、安全停车、通信超时和控制来源切换也会解除该状态。退出小陀螺后恢复普通运动的 `0.10 / 0.40 rad` 滞回规则，初始对齐放行不会直接继承普通运动的放行状态。

本次没有提高 GM6020 电流上限、位置环速度上限或舵角目标推进速率。旋转时要求的舵角变化过快，仍可能因 `cos³` 补偿出现明显降速，需要结合实车反馈进一步调整旋转速度和舵向跟踪。

## 7. 云台参考与小陀螺平移

旧 V1 路径仍保留用于遥控/键鼠的兼容诊断：它以实时云台朝向为平移参考，接收相对车头的 yaw 角 alpha（逆时针为正）。当前 v4 底盘路径直接消费车身坐标 `vx/vy/wz`，不再从通信帧推导 alpha；旧路径的 `R(alpha)` 变换和旋转预测仍只在兼容输入源中生效。

UART7 输入始终是当前车身坐标，不使用云台角度；旋转时仅保留原有的 5 ms 预测与降速。旋转指令仍独立控制，不因云台朝向改变而自动跟随云台旋转。

云台角未收到、标记无效或超过 50 ms 未更新时，遥控平移置零，独立旋转保留，UART7 控制不受此角度链路影响。旋转中 IMU 无效仍禁止平移。USART10 每 10 ms 回传底盘角速度与有效性、控制源、驱动放行标志，忙时跳过。

`desired_velocity.vx/vy` 在遥控时为云台坐标指令，在 UART7 时为车身坐标指令；`actual_velocity.vx/vy` 是转换后的车身指令，并非里程计。保留的 `spin_translation_reference_yaw`、`spin_translation_relative_yaw` 是诊断量，不再参与平移变换。关闭 `kRobotChassisSpinTranslationEnabled` 只关闭旋转预测和降速，遥控仍需实时云台相对角转换。

USART10 原视觉功能默认关闭，现由底盘 v4 板间链路使用；编译期禁止同时启用视觉串口。旧 V1 API 仅为迁移兼容保留。v4 协议主文档、迁移要求和实现边界见 [底盘云台板间通信](底盘云台板间通信.md)。UART1 保持 20 通道 GM6020 PID 遥测，见 [FireWater_telemetry.md](../Skywalker/Application/FireWater_telemetry.md)。
