# GM6020 PID 调参 FireWater 遥测

UART1（PA9 TX、GND）以 **921600 baud、8N1** 向 VOFA+ 发送纯数字 CSV，选择 **FireWater** 协议。管理任务每 **10 ms** 发送一行，以 `\n` 结束，无表头，共 **20 个通道**。UART 忙时跳过当次发送，实际间隔可能超过 10 ms；6020 控制周期仍为 **2 ms**。启用裁判系统后停止这路遥测。

默认观察底盘 **GM6020 ID 1（左前）**。在 `app_robot.c` 顶部将 `ROBOT_GM6020_TELEMETRY_ID` 改为 1～4，或通过编译参数 `-DROBOT_GM6020_TELEMETRY_ID=2` 选择 ID 2。ID 2/3/4 分别为右前/左后/右后。这次修改替换了原来的 UART7/IMU 遥测通道；UART7 接收和底盘控制逻辑保持原有行为。

| 通道（从 0 开始） | 内容 | 单位 |
| --- | --- | --- |
| 0 | 当前观察的 GM6020 ID | 1～4 |
| 1 | 运动学请求角，映射到当前角附近的连续分支 | rad |
| 2 | 位置 PID 实际使用的目标角，含目标推进限速与跨圈分支选择 | rad |
| 3 | 编码器反馈的连续角 `continuous_angle` | rad |
| 4 | 位置 PID 本次计算的误差 `position_loop.error` | rad |
| 5 | 目标角速度 `given_omega`，位置模式下为外环输出 | rad/s |
| 6 | 实际角速度 `omega` | rad/s |
| 7 | 速度 PID 本次计算的误差 `speed_loop.error` | rad/s |
| 8 | 最终电流指令 `given_current`，与 CAN 打包前一致 | A，按工程换算 |
| 9 | 电机反馈电流 `current` | A，按工程换算 |
| 10 | 速度环 P 项：`kp × error` | A |
| 11 | 速度环 I 项：`ki × error_sum` | A |
| 12 | 电机反馈温度 | ℃ |
| 13 | CAN 反馈有效：收到反馈且帧龄 ≤ 50 ms | 0/1 |
| 14 | 控制已启动：反馈有效、舵角目标已初始化、电机使能 | 0/1 |
| 15 | CAN 反馈帧龄；尚未收到反馈时为 0，结合通道 13 判断 | ms |
| 16 | 位置环输出上限 `output_max` | rad/s |
| 17 | 速度环输出上限 `output_max` | A |
| 18 | 四轮驱动的舵向对齐放行状态 | 0/1 |
| 19 | 当前控制来源：0 为 DT7，1 为 UART7 | 0/1 |

位置控制未启动或改为速度模式时，通道 2 显示当前连续角、通道 4 显示 0，避免误读复位或旧的外环数据；停控时通道 1 也显示当前连续角。反馈超时时仍能看到最后的速度/电流反馈，须结合通道 13/14 判断是否有效。通道 14 是控制路径状态，不保证存在非零输出。

角度是**电机编码器方向**，不是底盘安装符号修正后的轮组舵角。连续反馈跨 0/2π 不跳变；通道 1 始终选择最近分支，接近 180° 时分支仍可能切换，以通道 2 为 PID 跟踪基准。PID 误差来自最近一次控制计算，CAN 反馈可能更新得更晚，因此通道 4/7 与实时目标减反馈可能存在小差异。P/I 项未单独限幅；最终电流还可能包含 D 项并受到输出限幅。

## 建议的调参顺序

采用**先速度内环，再位置外环**的手动小幅测试；这一顺序可参考 [MathWorks 的串级控制设计说明](https://www.mathworks.com/help/control/ug/cascaded-multi-loopmulti-compensator-feedback-design.html)。下面的测试幅度与增益调整比例是针对本工程的调试起点，最终参数需要实车波形确认。

先架空并固定底盘，调舵向时断开 3508 驱动电机动力，保留 6020 反馈。优先先调一台，再分别检查四台。保持有效非零运动指令，否则程序会进入 `steering_idle`、发零电流并复位两个 PID，不能用摇杆归中后的停转来评价闭环收敛。DT7 在线时优先遥控；使用 UART7 时让 DT7 离线，并持续发送有效运动帧，间隔小于 100 ms。观察通道 13/14 均为 1。

### 1. 速度环

- 调试器中选择 `g_robot.chassis_motor_6020[id - 1]`，暂时将 `.mode` 改为 `kDjiMotorModeSpeed`。此模式下 `DjiMotorCurrentCalculate()` 不再用位置环覆盖 `given_omega`。保持运动指令有效，通过调试器修改 `.state.given_omega`，依次测试 `0 → 1 → 0 → -1 → 0 rad/s`，各平台约 0.5～1 s。控制仍开启时的 0 rad/s 是闭环制动；遥控归中会退出闭环。关注机构转动范围，采用短时间的小速度测试。
- 初始令 `.state.speed_loop.ki = 0`、`kd = 0`，从现有 `kp = 0.20` 起试。电流上限先保持 `0.8 A`。主要叠加通道 **5/6**，另开图观察 **8/9/10/11**。
- 响应慢且未长期限流时，每次将 Kp 增加约 10%～20%；出现速度反复振荡、电流快速正负切换时降低 Kp。无需刻意调到持续振荡。
- Kp 稳定后，只有持续存在速度偏差时才逐步加入 Ki。每次增大后观察稳态误差和回零/反转超调。若通道 11 长时间维持很大或反转拖尾，降低 Ki。速度环通常先用 PI，D 保持 0；本实现微分没有滤波，转速噪声可能被放大。
- 通道 8 长期贴着 ±通道 17，说明电流已限幅；此时继续加 Kp 通常不能解决跟踪不足，先检查负载、摩擦和供电。参数改变后应在静止时清除旧的积分/微分状态，或重新启动测试。

### 2. 位置环

- 恢复 `.mode = kDjiMotorModePosition`，固定已调好的速度环。先使用位置 **P** 控制，Ki/Kd 为 0，从比现有 `40` 更低的 Kp（例如 `10`）开始试，逐步上调。
- 使用持续有效的非零平移指令改变运动方向，使请求舵角先变化约 5°，再试 15°～30°及反向变化。先关闭旋转输入。不要直接写 `given_angle` 作为测试目标：它会被 `RobotSteeringUpdateTarget()` 在下个控制周期覆盖。
- 叠加通道 **1/2/3**，同时看 **4/5/6/8**。通道 1 到 2 的延迟是目标推进限速；通道 2 到 3 的延迟才主要反映闭环跟踪。增大外环 Kp 直到跟踪足够快，出现过冲或来回找角时回退；若速度内环本身在振荡，先回到内环处理。
- 现有目标推进上限和外环输出上限均为 **4 rad/s**。外环 `Kp=40` 时，角误差约 **0.1 rad（5.7°）** 已触发速度限幅。大角度转向速度受限时，增大 Kp 不会继续提升最大转速。
- 先保持外环 Ki 为 0。当前外环 `integral_max = 0`，仅修改 Ki 不会产生积分作用；确需积分时须同时设计积分限幅。优先用稳定内环与外环 P 消除问题。

### 3. 保存与验收

`PidInit()` 将配置复制进每个电机的 `PidObject`：运行中调 `.state.speed_loop/position_loop.kp/ki/kd` 才会立即生效。满意后将参数写回 `RobotSharedInit()` 中的 `chassis_gm6020_speed_pid` 和 `chassis_gm6020_position_pid`，重新编译下载；当前四个舵向电机共用这两份初始化配置。临时的速度模式也须恢复为位置模式。

最后检查四台电机的双向小角度响应、跨圈响应，再恢复驱动动力验证低速平移和旋转。每次仅改变一个参数，记录上升时间、超调、稳定后的误差和电流饱和情况。遥测是 100 Hz，可能漏掉更高频的振荡；本次未提高发送频率。
