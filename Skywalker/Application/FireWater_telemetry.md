# GM6020 调试 FireWater 遥测

UART1（PA9 TX、GND）以 **921600 baud、8N1** 向 VOFA+ 发送纯数字 CSV，选择 **FireWater** 协议。管理任务每 **10 ms** 发送一行，以 `\n` 结束，无表头，共 **5 个通道**。UART 忙时跳过当次发送，实际间隔可能超过 10 ms；6020 控制周期仍为 **2 ms**。启用裁判系统后停止这路遥测。

默认观察底盘 **GM6020 ID 1（左前）**。在 `app_robot.c` 顶部将 `ROBOT_GM6020_TELEMETRY_ID` 改为 1～4，或通过编译参数 `-DROBOT_GM6020_TELEMETRY_ID=2` 选择 ID 2。实车轮组按俯视左上角为 ID1、逆时针递增：ID1 左前、ID2 左后、ID3 右后、ID4 右前。遥测代码会按 CAN ID 映射到对应物理轮位。

| 通道（从 0 开始） | 内容 | 单位 |
| --- | --- | --- |
| 0 | 遥控器左摇杆 ch3 归一化值 | -1～1 |
| 1 | 运动学请求角，映射到当前角附近的连续分支 | rad |
| 2 | 位置 PID 实际使用的目标角，含目标推进限速与跨圈分支选择 | rad |
| 3 | 编码器反馈的连续角 `continuous_angle` | rad |
| 4 | CAN 反馈有效：收到反馈且帧龄 ≤ 50 ms | 0/1 |

## 判读

- 通道 0 不动：遥控通道或接收机没有读到左杆。
- 通道 0 动、通道 1 不动：平移指令没有进入舵向解算，重点查控制来源、云台相对角或 `steering_idle`。
- 通道 1 动、通道 2 不动：目标推进或舵角初始化有问题。
- 通道 2 动、通道 3 不动：6020 反馈、CAN 或电机问题。
- 通道 4 为 0：6020 反馈超时，先查 FDCAN1 `0x205~0x208` 和电机 ID。

角度是**电机编码器方向**，不是底盘安装符号修正后的轮组舵角。连续反馈跨 0/2π 不跳变；通道 1 始终选择最近分支，接近 180° 时分支仍可能切换，以通道 2 为 PID 跟踪基准。位置控制未启动或改为速度模式时，通道 2 显示当前连续角，避免误读复位或旧的外环数据。

## PID 调参

当前固件只输出上述 5 个调试通道，不再输出原来的速度环、电流、温度等 20 通道布局。需要按速度环/位置环完整调参时，可从 Git 历史中取回旧版 `RobotFormatGm6020Telemetry()` 和对应的 `FireWater_telemetry.md`；或临时扩展本函数后再调。

调参前仍建议架空并固定底盘，调舵向时断开 3508 驱动电机动力，保留 6020 反馈；保持有效非零运动指令，否则程序会进入 `steering_idle`、发零电流并复位两个 PID，不能用摇杆归中后的停转来评价闭环收敛。
